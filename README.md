# 🤖 Telegram Bot — Подача заявок на оплату счетов

**Корпоративный Telegram-бот** для автоматизации подачи заявок на оплату счетов сотрудниками. Интегрирован с **Битрикс24**, **Google Таблицами** и **Google Drive**. Все данные синхронизируются в реальном времени, доступ управляется через корпоративный портал.

## Как это работает

### Диалог с ботом

Сотрудник в Telegram нажимает кнопку **«Оставить новую заявку»** (или отправляет `/start`). Бот пошагово собирает данные:

| Шаг | Поле | Формат |
|-----|------|--------|
| 1/5 | Плановая дата оплаты | `ДД.ММ.ГГГГ` |
| 2/5 | Наименование контрагента | Текст |
| 3/5 | Сумма и код валюты | `15000 RUB` |
| 4/5 | Статья расхода | Выбор из справочника |
| 5/5 | Комментарий | Текст или пропустить |
| — | Файл счёта | PDF, изображение или пропустить |

После заполнения бот показывает **HTML-сводку** с кнопками «Изменить» у каждого поля. Сотрудник может скорректировать любые данные перед подтверждением.

### Что происходит при подтверждении

1. **Google Таблица** — данные записываются в таблицу (11 столбцов A–K)
2. **Google Drive** — файл счёта сохраняется в папку `Счет_№N.ext`
3. **Битрикс24** — автоматически создаётся задача на ответственного сотрудника
4. **Telegram-уведомление** — если дата оплаты = сегодня, ответственному приходит личное сообщение
5. **Групповой чат** — каждая заявка дублируется в общий чат компании

## Безопасность и идентификация

### Централизованное управление доступом через Битрикс24

Доступ к боту имеют **только активные сотрудники**, чей Telegram ID внесён администратором в систему Битрикс24. Никаких отдельных списков, паролей или ручных настроек — всё управляется через единый корпоративный портал.

**Как это работает:**

1. Администратор Битрикс24 заполняет у сотрудника скрытое пользовательское поле **«Telegram ID»**
2. Пользователь **не видит и не может редактировать** это поле — только администратор
3. При каждом сообщении бот делает запрос в Битрикс24: `user.get?FILTER={ACTIVE:true}`
4. Если сотрудник есть в списке активных — доступ разрешён
5. Если сотрудник **деактивирован/уволен** — доступ мгновенно блокируется

### Защита от подмены личности

- **Telegram ID** — неизменяемый идентификатор, проверяемый серверами Telegram. Подделать невозможно
- **Имя и Фамилия** — всегда подтягиваются из Битрикс24. Даже если пользователь изменит имя в Telegram, в заявке будет указано корпоративное имя
- **ID сотрудника (столбец K)** — в таблицу записывается уникальный идентификатор `bitrix_id`. Даже при совпадении имён всегда известно, кто именно создал заявку
- **Связка Telegram ID → Bitrix24 ID** — нерушима на уровне API. Пользователь не может выдать себя за другого сотрудника

### Сценарии безопасности

| Событие | Результат |
|---------|-----------|
| Сотрудник уволен/деактивирован в Битрикс24 | Доступ мгновенно заблокирован |
| Сотрудник сменил Telegram-аккаунт | Администратор обновляет поле — доступ восстановлен |
| Сотрудник изменил имя в Telegram | В заявке — корпоративное имя из Битрикс24 |
| Попытка доступа неавторизованного пользователя | «Доступ закрыт. Обратись к руководителю отдела» |

### Защита данных

- **Google-доступ** — через сервисный аккаунт (не OAuth пользователя). Файлы счетов доступны только через явно выданные права
- **Приватный ключ** — хранится в `credentials.json` (в `.gitignore`, никогда не коммитится)
- **Токены и секреты** — только в `.env` (права `600`, не коммитятся)
- **Файлы счетов** — после загрузки права доступа ограничиваются
- **Логирование** — все действия пишутся в Grafana Loki для аудита

### Поток данных при создании заявки

```
Пользователь → /start
  │
  ├─ Middleware: Bitrix24 API → проверка ACTIVE + Telegram ID
  │   └─ Найден? → auth_ok (employee_obj в контекст)
  │   └─ Не найден? → ApplicationHandlerStop («Доступ закрыт»)
  │
  ├─ ConversationHandler: 5 шагов + файл
  │
  └─ Подтверждение:
      ├─ get_next_invoice_id() → Sheet API (чтение max ID)
      ├─ upload_file_async()   → Drive API (Счет_№N.ext)
      ├─ append_row_async()    → Sheet API (11 столбцов)
      ├─ create_task()         → Bitrix24 API (tasks.task.add)
      ├─ send_message()        → Telegram (уведомление, если дата = сегодня)
      └─ send_message()        → Telegram (дублирование в группу)
```

## Установка и настройка

### Быстрый старт

```bash
git clone https://github.com/Ivan-Baidyk/tg-invoice-bot.git
cd tg-invoice-bot
python3 setup.py   # Интерактивный мастер настройки
uv sync            # Установка зависимостей
uv run python bot.py
```

### Systemd (production)

```bash
cat > /etc/systemd/system/invoice-bot.service << 'EOF'
[Unit]
Description=Invoice Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/invoice-bot
ExecStart=/opt/invoice-bot/.venv/bin/python3 -u bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now invoice-bot
```

### Предварительные требования

1. **Telegram бот** — создаётся через [@BotFather](https://t.me/BotFather)
2. **Google Cloud** — сервисный аккаунт с доступом к Sheets API и Drive API
3. **Bitrix24** — входящий вебхук для REST API
4. **Google Таблица** — с листами «Заявки» (A–K) и «Справочник» (A:A)
5. **Google Drive** — папка для хранения файлов счетов

## Переменные окружения

Настраиваются через `python3 setup.py` или вручную в `.env`:

### Telegram

| Переменная | Описание | Пример |
|-----------|----------|--------|
| `BOT_TOKEN` | Токен бота от @BotFather | `8857034898:AAG...` |
| `ALLOWED_CHAT_ID` | ID группового чата для дублирования | `-5562698707` |

### Bitrix24

| Переменная | Описание | Пример |
|-----------|----------|--------|
| `BITRIX24_WEBHOOK_URL` | Webhook URL для REST API | `https://b24-xxx.bitrix24.ru/rest/1/token` |
| `BITRIX24_TELEGRAM_FIELD_ID` | ID кастомного поля с Telegram ID пользователя | `UF_USR_1785740541166` |
| `BITRIX24_POSITION_FIELD_ID` | ID кастомного поля с должностью | `UF_USR_XXXXXXXXXX` |
| `URGENT_NOTIFY_POSITIONS` | Должности для уведомлений (через запятую) | `["Бухгалтер","Финансовый директор"]` |

### Google

| Переменная | Описание |
|-----------|----------|
| `GOOGLE_SHEET_ID` | ID Google Таблицы (из URL) |
| `GOOGLE_DRIVE_FOLDER_ID` | ID папки Google Drive для счетов |

### Прочее

| Переменная | Описание | По умолчанию |
|-----------|----------|-------------|
| `PROXY_URL` | Прокси для Telegram API (если заблокирован) | (пусто) |
| `LOKI_URL` | URL Grafana Loki для логов | (пусто) |
| `MAX_INVOICE_FILE_SIZE_MB` | Макс. размер файла счёта | `10` |

## Структура Google Таблицы

### Лист «Заявки» (основной)

| A | B | C | D | E | F | G | H | I | J | K |
|---|---|---|---|---|---|---|---|---|---|---|
| ID счета | Дата внесения | План. дата | Сотрудник | Контрагент | Сумма | Статья | Статус | Комментарий | Ссылка | ID сотр. |

- **A** — автоинкремент (бот вычисляет max + 1)
- **G** — всегда «Новый», data validation из выпадающего списка
- **J** — ссылка на файл в Google Drive
- **K** — ID сотрудника из Битрикс24 (для аудита)

### Лист «Справочник» (статьи расхода)

| A |
|---|
| Канцелярия |
| Оборудование |
| ПО и лицензии |
| ... |

Бот читает столбец A **при каждом запросе** — без кэширования. Добавили статью в таблицу → она сразу доступна всем пользователям.

## Бизнес-процессы

### Управление доступом

```
Администратор Битрикс24
  │
  ├─ Приняли сотрудника → заполнил UF_TelegramID → доступ открыт
  ├─ Сотрудник сменил Telegram → обновил UF_TelegramID → доступ восстановлен
  └─ Сотрудник уволен → деактивировал в Битрикс24 → доступ мгновенно закрыт
```

**Ключевое преимущество:** единая точка управления. Не нужно заходить в админку бота, править конфиги или перезапускать сервис. Все изменения применяются в реальном времени.

### Актуальный справочник статей

Ответственное лицо (финансовый директор, главный бухгалтер) ведёт справочник статей расхода в Google Таблице на листе «Справочник». При добавлении новой статьи она **сразу** появляется в боте у всех сотрудников. Это исключает:

- Несогласованность справочников между системами
- Использование устаревших или нестандартных статей
- Человеческий фактор при ручном заполнении

### Автоматические задачи в Битрикс24

При создании заявки бот автоматически формирует задачу в Битрикс24:

| Поле задачи | Значение |
|------------|----------|
| Название | `Оплата счёта №X: Контрагент — Сумма` |
| Описание | Полные данные заявки + ссылка на счёт |
| Ответственный | Сотрудник с указанной должностью |
| Постановщик | Сотрудник, создавший заявку (ID из Битрикс24) |
| Срок | Плановая дата оплаты, 18:00 |

Это реализует принцип **«задача на каждое действие»** — эффективную методологию управления, где ни одна операция не теряется.

### Уведомления

- **Срочные** (дата оплаты = сегодня) — личное сообщение ответственному в Telegram + задача в Битрикс24
- **Обычные** — только задача в Битрикс24
- **Все заявки** — дублируются в групповой чат компании

## Безопасность данных

### Google-авторизация

Используется **сервисный аккаунт** Google Cloud — не OAuth пользователя:

- Не требуется браузер или интерактивная авторизация
- Права доступа выдаются явно через Google Console
- Приватный ключ хранится в `credentials.json` (исключён из репозитория)

### Стек безопасности

```
1. Telegram API → immutable user_id (нельзя подделать)
2. Bitrix24 API → поиск user_id в UF_TelegramID активных сотрудников
3. Pydantic → валидация всех входных данных
4. MIME-type фильтр → только разрешённые форматы файлов
5. Размер файла → ограничение через MAX_INVOICE_FILE_SIZE_MB
6. .env + credentials.json → chmod 600, в .gitignore
7. Системные права → MemoryMax, RestartSec, ротация логов
```

### Аудит и мониторинг

- **Grafana Loki** — все действия бота логируются структурированным JSON
- **Google Таблица** — полная история всех заявок
- **Битрикс24** — задачи фиксируются в CRM
- **ID сотрудника (столбец K)** — всегда известно, кто создал заявку
